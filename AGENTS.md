**Read `kit/AGENTS.md` first.** The deck kit ([rectoverso-deck-kit](https://github.com/rectoversohq/rectoverso-deck-kit), a submodule at `kit/`: `git submodule update --init kit`) holds what every deck follows: the deck contract, its check, and the rules for authoring, covers, languages, versions and releases. This file adds this deck’s own rules.

Read README.md, rectoverso.json, docs/course-brief.md and docs/review.md before authoring. This is a multilingual gallery deck at version 1.0.0, which the owner approved for release (2026-11-12). The owner authorized sequential construction of question types with two Astra reviewers at high effort: factual accuracy and pedagogy. The app repository is read-only.

## Authoring and review

Build one question type, validate its packages and rendered behavior, and address both reviewers before starting the next type. Record each review against item IDs and file hashes in docs/review.md and external evidence. Primary Japanese teaching sources substantiate facts. A content or signal check is not native-speaker listening approval.

The confirmed course brief owns pedagogy and scope. The owner decides final names, copy, sample, categories, coverage changes, covers and releases. Working metadata remains unapproved until reviewed. Add dated owner decisions to docs/decisions.md, preserving earlier entries.

Each language is complete. English is American English. French is France’s French: « guillemets », narrow no-break spaces before ; : ! ? and %, typographic apostrophes and …; a deck is « un deck ». Shared Japanese content and media have one source. Original prose/compositions are © Simon Pinkas, CC BY 4.0; font and audio terms retain their own provenance. The Japanese recordings are Microsoft’s Nanami voice, made through Azure AI Speech under Microsoft’s Product Terms for Azure (#6); scripts/synthesize_audio.py reads the Speech key from the login Keychain at run time, and the key never enters the repository, a log or a command line. The recordings are not CC BY 4.0 and not relicensed here: never present them as part of the deck’s own license.

## Source and contract

Source records live in source/, font masters in artwork/fonts/, tooling in scripts/, checks in scripts/checks/, and guides in docs/. scripts/source_data.py has two interfaces: course(language, …) is this course’s own expansion, with its components and the beginner trial, which the builder and the tests use; inputs(language) is the deck kit’s, returning what rectoverso.json declares for the language with the course’s notes, note types and deck, and refusing a rectoverso.json that states another count, sample, package or credit than the course makes. After a change to the questions or the artwork, run scripts/metadata.py, which writes those facts into rectoverso.json. The sample is not one of them: it is the owner’s choice of one card, named in rectoverso.json for each language. Build with scripts/build.py --language <code> --out <new external package>, optionally --type for separate review components and --artwork for retained external renders.

All generated packages, pictures, caches and evidence stay outside this source checkout on the SSD, with paths passed as arguments. The tracked artwork record contains filenames, geometry and hashes, not rendered PNGs. Rebuilds use pinned fonts and dependencies. Every image and sound has provenance, credits and hashes.

Keep GUIDs, model/field/template/deck IDs and package identities stable once studied. A payload’s book is the id RectoVerso derives from the package’s Anki deck (source_data.library_id), never a UUID of this course’s own: the gallery knows a deck on the shelf by it. GUIDs follow <guidPrefix>-<language>-<item>. Isolated component packages have distinct preview identities; they do not replace the earlier 15-card prototype or the final course. Stages affect introduction order only; reviews remain with FSRS. Custom metadata does not create app behavior; initial presets require app issue #805.

Prerequisites are part of the contract (app #876, the Library page’s “Prerequisites”): each note’s “RectoVerso” payload says what its card requires and what it introduces, as lists of this course’s own tokens (lowercase words and digits with hyphens: hira-3042, hira-marks-g). Only a card that teaches introduces: a reading introduces its kana, a rule its rule. A card requires everything it shows or asks that another card teaches: a listening, word, comparison, variant or checkpoint question its kana and rules, and a reading the other kana its answer’s row shows as taught (visibleKana). The app’s Lesson mode holds a card back until the cards that introduce what it requires have been answered. scripts/source_data.py writes both keys from the source’s requires/introduces and the artwork record; the complete course and the beginner trial carry them, a type preview declares nothing (it could not teach what it requires). The gallery’s check refuses a token no card of the package introduces, a card that could never come, and a deck’s order that asks before it teaches; tests/test_prerequisite_payload.py holds the packages to the same rules.

The authoritative contract is the deck kit’s, pinned at `kit/` (kit/docs/contract.md, kit/docs/card-payload.md, kit/docs/prerequisites.md): never edit a file under `kit/` from here, and a new field, value or form is a change to the kit, made there first. Moving the pin is a pull request of its own. publication.approved is the owner’s to set, edition by edition: the candidate 1.0.0-rc.4 was approved for the gallery in TestFlight and 1.0.0 for release, and a passing check is never itself an approval.

## Validation and Git

Run `python3 kit/check.py` after every change (kit/docs/check.md explains each refusal); with `--rectoverso`, as RectoVerso’s gallery takes a deck, which the workflow runs. scripts/checks/validate-anki.py checks two things, by the package it is given: a package built here, and RectoVerso’s own export of the deck (the gallery’s round trip), which holds the cards as the app’s notes, named by their card ids, without tags: there it holds every source note to its fields, kind, prerequisites, ids and media. Before presenting each type, check inventory, prerequisites, bilingual copy, sound/reveal placement, mask preservation and media integrity, then import/render/study/reimport with Anki. Inspect native iPhone/Duo light/dark behavior when the simulator is available and say exactly which checks remain unverified. The owner released the iPhone to Claude, then explicitly reauthorized simulator use on 2026-11-08. Respect current simulator locks. Pending native checks do not prevent sequential source/build work and dual content review. Keep failed evidence. Final combined sequencing is checked after every type exists.

Work on a codex/ branch in this source repository. Commit only owned files explicitly by name. App and other deck sources remain untouched. Source changes ultimately reach the owner by pull request; creating a remote repository, pushing, merging, tagging, publishing, changing gallery pins or editing the owner’s phone requires the applicable user instruction. Local review packages authorize none of those actions.
